What is being hashed, and what is not

The log is serialised to canonical JSON before hashing: keys sorted, fixed separators, and only in-world event dates. No execution timestamp goes in, or every run would differ by construction and the check would be worthless.

Two runs in one process is the weakest of the three checks and the only one you can see here. The test suite also re-runs each scenario in a separate process with PYTHONHASHSEED varied, which is what actually rules out a hidden dependence on dictionary or set iteration order, and compares against a hash recorded in the suite so a change in decision logic fails loudly instead of producing a different but self-consistent answer.
